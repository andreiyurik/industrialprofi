## Что вообще такое Arduino

«Arduino» — это не один продукт, а платформа из трёх частей: **плата** с микроконтроллером (обычно семейства AVR — Atmega328P на классической Uno) и обвязкой для удобного подключения, **среда разработки** (Arduino IDE) и **библиотека функций** (Arduino Core), которая прячет низкоуровневую работу с регистрами микроконтроллера за простыми командами вроде `digitalWrite()`. Именно третья часть и есть главная ценность для новичка: она сознательно жертвует контролем ради скорости первого результата.

> [!ВАЖНО]
> Плата Arduino Uno и микроконтроллер Atmega328P на ней — разные уровни абстракции. Когда в главе 3.3 ты перейдёшь на STM32 без Arduino Core, ты не будешь учить «другую Arduino» — ты будешь работать с микроконтроллером напрямую, тем самым способом, каким работает Arduino Core под капотом. Это не шаг в сторону, а шаг вглубь той же темы.

## Цифровой вывод, «моргание» и цикл `loop()`

Программа Arduino устроена как две функции: `setup()` выполняется один раз при включении (настройка режимов выводов), `loop()` выполняется бесконечно по кругу (сама логика работы). Классический первый пример — мигание встроенным светодиодом:

```cpp
void setup() {
  pinMode(LED_BUILTIN, OUTPUT);   // назначаем вывод GPIO цифровым выходом
}

void loop() {
  digitalWrite(LED_BUILTIN, HIGH); // подать логическую единицу (обычно ~5 В или 3,3 В)
  delay(500);                      // подождать 500 мс
  digitalWrite(LED_BUILTIN, LOW);  // подать логический ноль (0 В)
  delay(500);
}
```

> [!ПРИМЕР]
> `digitalWrite()` не «включает светодиод» напрямую — она устанавливает электрический потенциал на конкретном выводе GPIO. Дальше уже сама схема на плате (резистор-ограничитель тока и светодиод, распаянные производителем платы) превращает это напряжение в свечение. Понимание этого различия — граница между «я скопировал пример» и «я знаю, что происходит»: тот же `digitalWrite(HIGH)` на другом выводе, к которому подключено реле, включит совсем другую нагрузку, а не светодиод.

Пока это единственный вывод — GPIO на цифровой выход. Аналоговый ввод-вывод и ШИМ — тема [следующей практики](/ru/lessons/gpio-shim-acp-na-praktike).

## Почему `delay()` — это ловушка для следующего шага

`delay()` останавливает выполнение всей программы на заданное время — просто и понятно, но пока плата «спит» в delay, она не может ничего больше делать: ни читать кнопку, ни отвечать по UART. Это работает для первой программы, но перестаёт работать, как только нужно делать несколько вещей одновременно (моргать светодиодом *и* следить за кнопкой) — эта проблема и её решение через таймеры и прерывания разбирается в следующем разделе главы.
