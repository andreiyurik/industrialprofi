# No notification bell

The loop a bell would serve is already closed more cheaply: `notify-dot` on the
account/hamburger button → dashboard «Мои правки» (rendering = seen) → an outcome
email only as the unread-24h fallback. A `Notification` model would add a per-user
table, fan-out, read state and a list UI for the one event type that exists
(suggestion outcomes) — and an empty bell reads as a dead platform pre-launch.
