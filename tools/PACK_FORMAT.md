# Контент-пак — публичный контракт формата (format: 1)

Пак — это одна профессия в виде дерева YAML/Markdown-файлов, упакованного в zip.
**Дерево — единственный канонический формат обмена контентом; zip — только
транспорт.** Всё, что умеет читать и писать платформа, ходит через него:
`/admin/paths/<slug>` → «Экспорт» отдаёт пак, `/admin/imports` принимает его
обратно с предпросмотром, `bin/rails content:export[slug]` /
`content:import[slug]` делают то же из репозитория. Пак обязан иметь смысл и
без платформы: внутри нет инстанс-специфичных токенов, подписанных URL или
привязок к конкретной базе.

Этот файл — контракт для всех, кто производит паки: экспертов, работающих
офлайн, LLM-инструментов (см. `AUTHOR_PROFESSION.md`), других установок
платформы. Второго формата не существует и не должно появиться.

## Дерево

```
<slug-профессии>/
├── pack.yml                     # манифест
├── path.yml                     # профессия
├── landing.yml                  # лендинг «О профессии» (необязателен)
├── 01-<slug-главы>/
│   ├── course.yml               # глава
│   ├── 01-section/
│   │   ├── section.yml          # раздел (заголовок-группа внутри главы)
│   │   ├── <slug-статьи>.md
│   │   └── <slug-статьи>.md
│   └── 02-section/…
└── 02-<slug-главы>/…
```

- Порядок глав и разделов задаётся сортировкой имён каталогов (`01-…`, `02-…`),
  порядок статей — сортировкой имён файлов внутри раздела. Если статьи раздела
  упорядочены не по алфавиту, экспортёр честно разбивает его на соседние
  каталоги-разделы с одинаковым `title` — импорт воспроизводит точный порядок.
- Slug профессии — имя корневого каталога (zip, собранный «изнутри» каталога,
  получит slug из заголовка). Slug статьи — имя `.md`-файла.
- **Slug статьи уникален глобально**, на всю платформу, не только внутри
  профессии — уже занятый slug импорт отвергнет как конфликт.

## pack.yml — манифест

```yaml
format: 1                        # версия формата
exported_at: "2026-07-31T…"      # информационно; единственный таймстамп пака
courses: 7                       # информационно
lessons: 52                      # информационно
```

Импортёр **отказывается** от пака более нового формата (`format` больше, чем он
понимает) — вместо того чтобы прочесть его наполовину. Манифест опционален
(старые экспорты), отсутствие = формат 1. Всё, кроме манифеста, экспортируется
детерминированно: два экспорта одного состояния дают одинаковые байты, паки
диффабельны.

## path.yml и course.yml

```yaml
title: "Электрик"                # обязателен
description: "…"                 # зачем идти в профессию
icon: "lightning"                # эмблема из набора платформы; можно опустить
status: draft                    # честный статус; через /admin/imports всегда ложится draft
position: 1                      # порядок в каталоге; информационно для пака
```

`course.yml` дополнительно несёт `slug:` (иначе выведется из title).

## landing.yml — лендинг «О профессии»

Шесть слотов, одинаковых для любой профессии в любой стране; всё национальное и
отраслевое (разряды, профстандарты, зарплаты) — прозой внутри слотов, не полями.
Каждый слот необязателен: пустой не показывается. Текстовые слоты — Markdown,
списочные — массив строк.

```yaml
about: |                         # 2–4 абзаца: чем занимается, где работает, как растёт
  …
highlights:                      # что умеет мастер, 4–6 строк
  - "Читает схемы и собирает щит по ним"
pros: ["…"]                      # сильные стороны, 3–5
cons: ["…"]                      # слабые стороны, 3–5 — честно
history: |                       # 1–2 абзаца, вехи текстом
  …
faq: |                           # вопросы — заголовками ###, ответы абзацами
  ### Сколько учиться?
  …
cover_credit: "Фото: …, Wikimedia Commons, CC BY-SA 4.0"   # подпись к обложке, если её загрузили в админке
```

Пустой лендинг заполняется из пака даже у профессии, которую уже правил человек
(это создание, не перезапись); непустой — только пока профессия нетронута, как
любое другое поле.

Обложки пак не переносит: картинку профессии добавляют в форме профессии в
админке — файл `cover.*` в паке игнорируется. Неизвестная эмблема не ошибка:
она пропускается со строкой в отчёте, запись наследует эмблему по умолчанию.

## section.yml

```yaml
title: "Правила устройства"      # заголовок группы статей в программе главы
```

## Статья — `<slug>.md`

Три блока, разделённые строками `---`: YAML-frontmatter → ЗАЧЕМ → тело.

```markdown
---
title: "ПУЭ глава 1.7 — заземление"
kind: practice                   # только у практики; по умолчанию lesson
difficulty: intermediate         # только у практики: beginner|intermediate|advanced
resources:
  - title: "ПУЭ, изд. 7"
    url: "https://…"
    kind: norm                   # norm|book|document|course|video|article|software|tool
    required: true               # опустить = рекомендуемое
    language: ru                 # маркер языка источника
    country_code: ru             # опустить = универсальный источник
    note: "Гл. 1.7, разделы …"   # «что именно смотреть» — одной строкой
terms:                           # сокращения, которые разбирает статья; из них
  - term: "УЗО"                  # собирается словарь профессии (вкладка «Словарь»)
    full: "Устройство защитного отключения"
    note: "одна строка: зачем это знать"   # опционально
    analog: "RCD"                # опционально: честный аналог в другой системе
                                 # обозначений (не перевод); если аналог есть в
                                 # словаре своей записью, страница свяжет их якорем
---
Одно самодостаточное предложение ≤155 символов: зачем тратить время на статью.
---
Тело статьи в Markdown…

## Задание

Бриф практики (Цель → Понадобится → [!ОПАСНО] → Шаги → Что сдать → Самопроверка).
```

- Блок после второго `---` — поле `description` (ЗАЧЕМ, он же SEO-сниппет).
- `## Задание` (ровно такой заголовок) отрезается в отдельное поле `task` —
  всё до него остаётся телом.
- Callout'ы — цитаты с маркером первой строкой: `> [!ВАЖНО]`, `> [!СОВЕТ]`,
  `> [!ОПАСНО]`, `> [!ПРОВЕРЬ]`. Рубрика качества статьи — `AUTHOR_PROFESSION.md`.
- Каталог `images/` в формате зарезервирован, но пока **не** импортируется —
  загрузка честно предупредит.

## Что гарантирует импортёр

- **Предпросмотр без записи**: `/admin/imports` сначала показывает dry-run-план;
  без подтверждения в базу не попадает ничего.
- **Через админку всё ложится черновиком** (`origin: ai`) — публикует человек,
  через обычную лестницу доверия.
- **Заморозка человеческого**: реимпорт обновляет только строки, которых не
  касалась рука человека; отредактированное экспертом не перезаписывается
  никогда (подробности — `CONTENT_FACTORY.md`, § 5).
- Разбор zip идёт целиком в памяти, без распаковки на диск (это же — защита от
  zip-slip). Лимиты: 20 МБ архив, 5 МБ файл, 2000 файлов.
- `icon:` применяется только при создании записи — реимпорт никогда не меняет
  эмблему, выбранную куратором.

## Версионирование

Формат меняется только с ростом `format:` в манифесте. Новый импортёр обязан
читать все старые форматы; старый импортёр обязан отказаться от нового формата
целиком. Ломающее изменение без роста версии — баг.
