# Промпт: SEO-перелинковка профессии внутренними @-ссылками

Переиспользуемый промпт для **нового чата** (Claude Code в этом репозитории).
Добавляет внутренние ссылки `[текст](/lessons/<slug>)` в статьи **одной опубликованной
профессии** — «ткань википедии профессий». Это главный SEO-рычаг (внутренняя
перелинковка = структура сайта для поисковика) и удобная навигация для читателя.

## Как пользоваться

1. Открой **новый чат** в этом репозитории.
2. Скопируй всё ниже `=== ПРОМПТ ===` в первое сообщение и укажи **slug профессии**
   (например `elektrik`, `svarshchik`, `operator-cnc`, `inzhener-asu-tp`).
3. Модель прочитает контекст, скурирует карту якорей и прогонит скрипт с проверкой.

Один прогон = одна профессия. Начинай с той, где больше всего «сирот» (у электрика
их было ~61 — там наибольший эффект).

## Задача

Добавь внутренние ссылки на другие статьи в тела статей профессии **<SLUG>**. Цель —
чтобы каждая содержательная статья ссылалась на 3–7 связанных статей (норма
`content:audit`): это SEO-структура сайта И удобная навигация «куда копать дальше».
**Качество и релевантность важнее количества. Битая ссылка хуже её отсутствия.**

## Главный принцип — делай ЭКОНОМНО (это важно)

**НЕ читай все тела статей языковой моделью и НЕ редактируй их по одной** — это
дорого по токенам. Вместо этого:

1. Построй **карту «отличительная тема → slug статьи»** из ЗАГОЛОВКОВ статей (дёшево).
2. Вставь инлайновые ссылки **скриптом** (шаблон ниже) — на первое упоминание темы.

Скрипт-подход в ~10–20 раз дешевле, чем агент, читающий каждую статью, и при
аккуратном подборе якорей даёт релевантные, безопасные ссылки.

## Умный подбор якорей — это ядро качества

Якорь = **отличительная, конкретная тема, у которой есть своя статья**. Хорошие якоря:
«запорная арматура», «наряд-допуск», «водомерный узел», «пресс-фитинг»,
«балансировка», «аксонометрия», «релейная защита», «токовая петля 4–20 мА».

- **НЕ бери общие слова**, которые встречаются повсюду («вода», «труба», «давление»,
  «система», «ток», «работа», «монтаж») — они дадут шумные, нерелевантные ссылки.
- Предпочитай **многословные/специфичные** фразы одному общему слову.
- Каждый якорь → **ровно один** самый релевантный целевой slug.
- Пропусти как ЦЕЛИ практики (`kind: practice`) и обзорные/мета-статьи — их темы
  слишком общие; ссылаться ЛУЧШЕ на конкретные теоретические статьи.
- Учитывай **русские окончания** (склонение): в regex после основы ставь
  `[а-яёА-ЯЁ]*`, а перед основой — границу `(?<![а-яёА-ЯЁ])`.

## Безопасность (обязательные инварианты)

- **Только существующие slug.** Скрипт берёт список slug из БД и линкует лишь на них —
  битых ссылок быть не должно (проверишь: `content:audit` → 0 битых).
- **Первое упоминание** темы в статье, **≤4 ссылки на статью**, **не на себя**.
- **Только в прозе**: пропускай заголовки (`#`), таблицы (`|`), блоки кода (```),
  и строки, где уже есть `](/lessons/` (не дублируй).
- **Не трогай frontmatter** (шапку до 3-го `---`: `---` frontmatter `---` ЗАЧЕМ `---` тело).

## Рабочий процесс

**Шаг 0 — контекст.** Прочитай `CLAUDE.md` (модель контента, правило внутренних
ссылок) и `tools/CONTENT_FACTORY.md`. Убедись, что профессия опубликована.

**Шаг 1 — список статей (дёшево).**
```
bin/rails runner 'Path.find_by(slug:"<SLUG>").lessons.includes(:course).sort_by{|l|[l.course.position,l.position]}.each{|l| puts "#{l.slug}\t#{l.kind}\t#{l.title}"}'
```

**Шаг 2 — скурируй карту якорей.** По заголовкам подбери 10–20 высокоточных якорей
(тема → slug). Выпиши их. Проверь себя: не попало ли общее слово? Многословны ли
фразы? Существует ли целевой slug?

**Шаг 3 — прогони скрипт** (шаблон ниже; подставь `ROOT` и `ANCHORS`). Скрипт логирует
**каждую** вставку «статья: «фраза» → /lessons/target». **Просмотри лог** — если видишь
нерелевантную ссылку, убери этот якорь и перезапусти (git checkout затронутых файлов
перед повтором, чтобы не наслаивать).

**Шаг 4 — залей и проверь.**
```
bin/rails content:import[<SLUG>]
bin/rails runner 'p=Path.find_by(slug:"<SLUG>"); known=Lesson.pluck(:slug).to_set; ls=p.lessons.select(&:has_body?); o=ls.select{|l| l.linked_lesson_slugs.empty?}; b=ls.flat_map{|l| l.linked_lesson_slugs.reject{|s| known.include?(s)}}; puts "сирот: #{o.size}; всего ссылок: #{ls.sum{|l| l.linked_lesson_slugs.size}}; битых: #{b.size}"'
```
**Битых должно быть 0.** Спот-чек: отрендери 2–3 статьи и глазами проверь, что ссылки
стоят в естественном месте, не внутри уже-ссылки, не в заголовке.

**Шаг 5 — второй проход по оставшимся сиротам.** Возьми скрипт, добавь условие
«обрабатывать только файлы БЕЗ `](/lessons/`» (см. коммент в шаблоне) и пару доп.
якорей под темы, что встречаются в оставшихся сиротах. Прогони, залей, перепроверь.

**Шаг 6 — остановись вовремя.** Когда дальнейшие ссылки становятся натянутыми —
**стоп**. Оставшихся сирот (обычно практики и статьи-мишени) НЕ форсируй: их удобнее
закрыть `@`-инструментом в редакторе при следующем редактировании. **Few-but-excellent.**

**Шаг 7 — git.** Ничего не коммить (политика репозитория). Оставь рабочее дерево на
ревью основателю; сообщи цифры (сирот было/стало, ссылок добавлено, битых 0).

## Скрипт-шаблон (адаптируй `ROOT` и `ANCHORS`)

Запускай **чистым ruby** из корня репо (без Rails — экономнее):
`ruby путь/к/скрипту.rb`

```ruby
require "pathname"
ROOT = Pathname("db/seeds/curriculum/<SLUG>")   # ← профессия
MAX_PER_LESSON = 4
def a(re, slug) = [/(?<![а-яёА-ЯЁ])#{re}/i, slug]

# Карта: отличительная тема (с учётом окончаний) → slug целевой статьи.
# Пример (замени под свою профессию!):
ANCHORS = [
  a('запорн[а-яёА-ЯЁ]*\s+арматур[а-яёА-ЯЁ]*', "03-...-armatura"),
  a('наряд-допуск[а-яёА-ЯЁ]*',                "02-...-narad-dopusk"),
  a('балансировк[а-яёА-ЯЁ]*',                 "03-...-balansirovka"),
  # ... 10–20 высокоточных якорей
]

# Тело статьи начинается после 3-го «---» (frontmatter / ЗАЧЕМ / тело). В теле
# бывают ещё «---» (гориз. линии) — поэтому именно 3-й сверху.
def body_start(lines)
  seen = 0
  lines.each_with_index { |l, i| (seen += 1) if l.strip == "---"; return i + 1 if seen == 3 }
  nil
end

total = 0
Dir.glob(ROOT.join("**/*.md")).sort.each do |file|
  text = File.read(file)
  # ВТОРОЙ ПРОХОД: раскомментируй, чтобы трогать только оставшихся сирот:
  # next if text.include?("](/lessons/")
  slug = File.basename(file, ".md")
  lines = text.lines
  start = body_start(lines) or next
  used = []; in_code = false; added = 0
  (start...lines.size).each do |i|
    line = lines[i]
    in_code = !in_code if line.strip.start_with?("```")
    next if in_code
    s = line.lstrip
    next if s.start_with?("#", "|", "```") || line.strip.empty?
    next if line.include?("](/lessons/")           # не дублировать ссылку в строке
    ANCHORS.each_with_index do |(re, target), idx|
      break if added >= MAX_PER_LESSON
      next if target == slug || used.include?(idx)
      next unless (m = line.match(re))
      line[m.begin(0)...m.end(0)] = "[#{m[0]}](/lessons/#{target})"
      lines[i] = line; used << idx; added += 1; total += 1
      puts "  #{slug}: «#{m[0]}» → /lessons/#{target}"
    end
  end
  File.write(file, lines.join) if added.positive?
end
puts "ИТОГО вставлено: #{total}"
```

## Ограничения

- Релевантность — прежде всего: лучше меньше отличных ссылок, чем много натянутых.
- Кросс-профессиональные ссылки допустимы, если статья реально смежна (проверь, что
  slug существует в `db/seeds/curriculum/` или в БД) — но не притягивай за уши.
- Не выдумывай slug. Скрипт линкует только на реальные цели из твоей карты.
- Не коммить и не пушь. Следуй `CLAUDE.md`.
